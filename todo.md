Recherche dans `content/` faite le 03/11/2026 : `Infrastructure & DevOps/Systèmes d'exploitation/composants-dun-ordinateur-et-demarrage.md` couvre déjà le bit et l'octet (section « Compter l'information »), la RAM volatile (un bit est un condensateur) et le SSD (cellules qui piègent des charges, flash qui garde ses données sans courant) ; `Infrastructure & DevOps/Systèmes d'exploitation/creer-un-systeme-d-exploitation.md` mentionne le code caractère (ASCII, Unicode) ; `Infrastructure & DevOps/Réseaux/fondamentaux-reseau.md` place le « support physique du signal (câble, Wi-Fi) » à la couche 1 du modèle OSI sans expliquer comment un bit devient un signal ; aucune occurrence de modulation, de démodulation ni d'amplitude ou de phase d'une onde. À ajouter : (1) `Infrastructure & DevOps/Réseaux/` : le trajet d'un fichier, du disque au signal. Seul l'état de chaque cellule est lu et copié (jamais les charges) : cellule chargée ou non (SSD) ou domaine aimanté dans un sens ou dans l'autre (disque dur) = 0 ou 1 ; le contrôleur du disque les lit, 8 bits forment un octet (exemple : `a` = 97 en ASCII = 01100001, avec le calcul 64 + 32 + 1), les octets passent en RAM puis à la carte réseau. (2) Même chapitre : la modulation, avec un tableau bit à envoyer / ce que produit l'émetteur / ce que mesure le récepteur (amplitude forte = 1, faible = 0 en version simplifiée ; le Wi-Fi fait varier amplitude et phase pour envoyer plusieurs bits par symbole, modulation QAM) ; la démodulation à la réception, la même carte réseau module et démodule (origine du mot modem) ; sur un câble Ethernet, des niveaux de tension codent les bits. Le support (câble, fibre, air) change, pas l'idée. (3) Comparaison Ethernet et Wi-Fi : Ethernet plus stable (pas d'interférences, pas de partage de l'air), le Wi-Fi traverse les murs mais s'intercepte par la portée des ondes (le chiffrement protège le contenu) ; piège relevé : un signal électrique n'est pas plus rapide qu'une onde radio (propagation voisine de la lumière dans les deux cas), c'est le débit stable qui diffère ; les niveaux d'un câble sont des tensions, pas des intensités. (4) Limites et alternative : taille des données contre débit (ce qui prend des heures à envoyer), RAM volatile (une coupure de courant en cours de transfert perd les données en mémoire), interception des ondes, bruit et erreurs de transmission ; envoyer le disque lui-même est l'alternative quand le volume est énorme. (5) Piège de vocabulaire : l'état de la charge, pas son « sens ».

Un service sans état (un outil d'administration comme Adminer) n'a pas de volume : ses fichiers sont dans l'image, et il agit sur la base en lui envoyant des requêtes par le réseau ; le volume de la base ne concerne que le serveur de base. L'avertissement `Docker Compose is configured to build using Bake, but buildx isn't installed` n'arrête pas la construction (constructeur classique, message `DEPRECATED: The legacy builder`, observé sur les paquets Ubuntu sans buildx).
- `Docker/volumes-et-reseaux.md` (pièges du bind mount) : au démarrage, l'image PostgreSQL donne son dossier de données à l'utilisateur `postgres` (UID 999) avec les droits 700 avant de vérifier s'il est vide. Observé le 04/11/2026 sur un dossier d'essai contenant deux entrées de l'utilisateur 1000 : propriétaire passé à 999, contenu illisible pour l'utilisateur d'origine, puis `initdb: error: directory ... exists but is not empty`. Donc ne jamais monter en bind un dossier qui sert à autre chose (un dossier parent de volumes inclus). Le dossier hôte d'un bind doit exister avant le démarrage : `mount ... no such file or directory` sinon, d'où le `mkdir -p` du `Makefile` ; `docker compose down -v` supprime le volume Docker mais laisse les fichiers du dossier hôte (observé : dossier de PostgreSQL resté).
- `Docker/dockerfile.md` (section sur `CMD` et `ENTRYPOINT`, vérifier avant d'ajouter) : en forme liste, chaque élément est un morceau de la commande lancée directement, sans shell. `CMD ["sleep 1"]` donne `exec: "sleep 1": executable file not found in $PATH` au lancement (observé le 04/11/2026) ; une variable comme `${VERSION}` n'y est pas remplacée (PHP a affiché le chemin avec `${ADM_VERSION}` littéral) ; un `ARG` n'existe qu'à la construction, pas dans le conteneur lancé.
- `Docker/dockerfile.md` (télécharger un fichier de façon vérifiée) : version et empreinte en `ARG`, `curl -fsSLo nom URL && echo "${EMPREINTE}  nom" | sha256sum -c -` (deux espaces entre l'empreinte et le nom). L'affichage de GitHub (API des releases) préfixe l'empreinte par `sha256:`, la forme attendue par `sha256sum -c` ne l'a pas (testé le 04/11/2026 : `Réussi` sans préfixe). Le fichier et son empreinte publiés au même endroit protègent d'une corruption, pas d'une source compromise (vérifier le lien avec le chapitre sur les sommes de contrôle avant d'ajouter).
- `Fondamentaux/Bases de l'informatique/serveur-local-de-developpement.md` (ligne 47, PHP) : `-t` attend un **dossier** (`/var/www/adminer/adminer-6.3.0-mysql.php is not a directory`) ; l'adresse `/` ne trouve rien sans fichier `index.php` ou `index.html` dans ce dossier (`The requested resource / was not found on this server`, observé le 04/11/2026) ; `0.0.0.0` dans un conteneur fait écouter sur toutes ses interfaces, sans quoi le port publié ne répond pas. Chaque adresse se découpe en protocole, machine et port, puis chemin : le serveur suit le chemin à partir du dossier racine qu'on lui donne.
- `Infrastructure & DevOps/Infrastructure/environnement-local-php-sql-server.md` ou un chapitre réseau (vérifier avant d'ajouter, une occurrence de `/etc/hosts` existe) : une ligne `127.0.0.1 nom.exemple` de `/etc/hosts` associe un nom inventé à une adresse sans passer par un DNS ; ce fichier est lu avant le DNS (`hosts: files mdns4_minimal [NOTFOUND=return] dns` dans `/etc/nsswitch.conf`, vérifié le 04/11/2026). Pour l'écrire : `echo "127.0.0.1 nom.exemple" | sudo tee -a /etc/hosts` (la redirection `>>` est faite par le shell sans `sudo`, donc refusée).
- `Langages/C/makefiles.md` (vérifier avant d'ajouter) : une valeur peut venir de trois sources, par ordre de priorité la ligne de commande (`make cible NOM=valeur`), les assignations du `Makefile` y compris celles d'un `include`, puis l'environnement du shell (`NOM=valeur make cible`, sans effet si le `Makefile` assigne déjà `NOM`) ; l'option `-e` donne la priorité à l'environnement ; `make -n` affiche les commandes d'une cible sans les exécuter, variables remplacées. Une variable donnée en ligne de commande est transmise aux commandes de la cible, une variable lue dans un `include` ne l'est pas (tableau mesuré le 04/11/2026 sur un `Makefile` jetable).
