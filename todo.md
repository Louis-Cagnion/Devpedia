## 7. Notions de SQL pour un premier contact (session `/professor` du 29/10/2026)

Recherche dans `content/` faite le 29/10/2026 : `Langages/Domain-specific Languages (DSL)/sql.md` couvre déjà les agrégats, `JOIN`, `CREATE TABLE` avec `PRIMARY KEY`, `NULL`, les index, PDO, l'injection SQL et le moindre privilège ; `Données/Bases de données/schemas-et-tables-techniques.md` couvre le schéma et `dbo` ; SSMS n'est cité que pour restaurer une sauvegarde `.bak`. - `Langages/Domain-specific Languages (DSL)/sql.md` : lire des lignes pas à pas, `SELECT` (choisir les colonnes), `FROM` (nom complet `schéma.table`), `WHERE` (le serveur teste chaque ligne contre la condition), `AND` et `OR`, `TOP n` (T-SQL) et son piège (il plafonne sans ordre précis, et le message « n lignes affectées » ne donne pas le total des lignes qui correspondent), le point-virgule qui termine une instruction entière et non une clause (`SELECT TOP` n'apparaît aujourd'hui que dans un exemple de `OUTER APPLY`).
- Même chapitre : types de colonne et valeurs cohérentes, un nombre s'écrit tel quel, un texte ou une date entre apostrophes, comparer un nombre à une date est une erreur de conversion, le format `'AAAA-MM-JJ'` sûr pour `date` mais pas toujours pour `datetime` selon la langue du serveur ; `numeric` et `decimal`, `varchar(n)` contre `char(n)`, `date` contre `datetime` ; le terme « clé primaire » (aucune occurrence dans `content/`, seul `PRIMARY KEY` est expliqué).
- Même chapitre : variable de table (`DECLARE @t TABLE (...)` puis `INSERT`), qui n'existe que le temps d'une exécution, s'écrit avec `@` dans `FROM`, ne crée rien de durable ; comparée à `CREATE TABLE` et à la table temporaire `#t` (aucune occurrence de « variable de table » ni de `DECLARE @` dans `content/`) ; utile pour s'exercer sans droit d'écriture sur une base.
- Même chapitre (ajouté le 29/10/2026, après-midi, même session) : trier le résultat avec `ORDER BY` (une colonne, `ASC` par défaut, `DESC`, placé après `WHERE`) ; pourquoi : une table n'a pas d'ordre garanti, donc sans tri l'ordre des lignes renvoyées est indéfini et peut changer d'une exécution à l'autre ; `TOP n` n'a de sens qu'avec un tri (sinon n lignes quelconques), et insérer les lignes dans l'ordre voulu ne remplace pas le tri pour la même raison ; limites : coût du tri sur une grosse table, ordre indéfini entre deux lignes de même valeur (seconde colonne de tri) ; quand l'éviter (compter, tester l'existence) ; ne pas confondre avec le filtre (`WHERE` retire des lignes, `ORDER BY` ne retire rien). `ORDER BY` n'apparaît aujourd'hui que dans un exemple sans explication (`sql.md`, ligne 125) et comme colonne à indexer (`les-index.md`).
- Même chapitre : lignes contre colonnes, avec le schéma d'une table (les colonnes sont verticales et se choisissent après `SELECT`, les lignes sont horizontales et se retirent avec `WHERE` et `TOP`), confusion rencontrée par un débutant ; `SELECT *` (toutes les colonnes) et le risque de l'écrire en dehors d'un essai, à compléter avec ce que Louis aura trouvé seul (aujourd'hui `sql.md` ne dit que « sélectionne toutes les colonnes », ligne 28).
- Même chapitre (ajouté le 29/10/2026, après-midi, même session) : ordre dans lequel le serveur traite une requête d'agrégation : `WHERE` filtre d'abord les lignes, `GROUP BY` forme les groupes, la fonction de calcul s'applique dans chaque groupe, `ORDER BY` trie en dernier (le total n'existe qu'après le calcul, d'où le tri possible sur son nom) ; `GROUP BY` ne trie pas : un ordre alphabétique observé est incident et non garanti, il faut `ORDER BY` (`GROUP BY ville DESC` est refusé, preuve que ce n'est pas un tri) ; sans `GROUP BY`, une fonction de calcul seule renvoie une ligne ; dans `COUNT(*)` l'étoile ne choisit pas de colonnes, elle compte des lignes ; la moyenne s'affiche avec plus de décimales que la colonne (`14700.000000`) ; erreur de débutant relevée : croire qu'un calcul porte toujours sur toute la table, alors qu'il porte sur les lignes gardées par `WHERE` ; limite à signaler : des valeurs mal saisies (orthographes proches) forment des groupes séparés. Aujourd'hui `sql.md` (lignes 30 à 53) donne les fonctions, `AS` et un exemple de `GROUP BY` sans ces points ; `HAVING` n'apparaît nulle part dans `content/` (non vu en séance, à ajouter quand il le sera).
