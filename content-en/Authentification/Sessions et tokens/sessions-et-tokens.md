# Sessions et tokens

Once identity is verified (see [Fondamentaux](/?c=authentification&s=fondamentaux&p=fondamentaux)), a concrete problem arises: how does the server remember that a user stays logged in from one HTTP request to the next? This subject covers the two classic answers to this question: the **session**, where the server keeps the login state on its own side, and the **token**, where that state is carried directly by the client on every request.
