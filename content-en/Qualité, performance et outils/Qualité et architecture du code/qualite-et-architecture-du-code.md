# Qualité et architecture du code

A program that produces the right result isn't necessarily one that's easy to change. This section gathers quality and architecture principles that don't depend on any particular language: they apply just as well to a [Python](/?c=langages-de-programmation&s=python&p=python) script as to a [JavaScript](/?c=langages-de-programmation&s=javascript&p=javascript) project or a C codebase.

The throughline is **maintainability**: code that's easy to understand, that doesn't repeat the same information in several places, and where a change stays localized rather than cascading. These principles aren't aesthetic rules: each one avoids a specific category of bug or regression, illustrated with a concrete case.
