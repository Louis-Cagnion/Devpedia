# OKRs

Every previous chapter in this subcategory deals with organizing **work**: how to break it down, estimate it, track it. One question remains unanswered: how do you make sure this work actually serves a larger purpose? **OKRs** (*Objectives and Key Results*) answer that question, by explicitly connecting day-to-day work to higher-level goals.

## Two parts, two different roles

An OKR always has two distinct components, each with a precise role:

| Element | Role | Trait |
|---|---|---|
| **Objective** | Where we want to go | Qualitative, ambitious, phrased as one inspiring sentence |
| **Key Results** | How we'll know we got there | Quantitative, measurable, 2 to 5 per objective |

```text
Objective: Become the reference for customer support in our industry

Key Results:
  KR1: Raise customer satisfaction from 72% to 90%
  KR2: Reduce first response time from 4h to 30 minutes
  KR3: Reach an 80% first-contact resolution rate
```

The objective alone ("become the reference for support") doesn't say whether it's been reached or not; the key results, on the other hand, are unambiguously verifiable on a given date.

> **Pitfall:** confusing a Key Result with a task to do ("Set up a new support software"). A task describes an action, a Key Result describes a measurable outcome; the same intent gets rephrased as a Key Result through its expected effect ("Reduce first response time to 30 minutes"), the task itself becoming one means among others of getting there.
>
> **Best practice:** always check that a Key Result is phrased as a verifiable measure (a number, a percentage, a threshold), never as a checkbox action.

## Connecting OKRs to daily work

The link to already-covered [backlogs and user stories](/?c=gestion-de-projet-et-organisation&s=gestion-de-projet&p=backlog-et-user-stories) happens naturally: each Key Result inspires the user stories that concretely contribute to reaching it, without the OKR itself going down to implementation-level detail.

```text
Key Result: Reduce first response time from 4h to 30 minutes
    │
    ├── User story: Add an automated response system
    │   for frequently asked questions
    ├── User story: Notify the support team in real time
    │   on a new ticket
    └── User story: Automatically prioritize urgent tickets
```

## Ambitious rather than guaranteed to be reached

Unlike a classic individual performance objective, an OKR is deliberately ambitious: a target achievement rate around 60-70% is often considered healthy, an OKR consistently reached at 100% suggesting a goal set too low to be genuinely stretching.

> **Pitfall:** using an OKR's achievement rate as an individual performance or evaluation measure, which mechanically pushes toward setting easy goals rather than ambitious ones, to avoid a bad score.
>
> **Best practice:** keep OKRs as a tool for collective alignment and direction, separate from any individual evaluation; an ambitious goal reached at 70% stays a positive signal, not a failure.
