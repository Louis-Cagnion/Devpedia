## 6. Notions repérées pendant l'auto-review de `42Cursus/Cercle 7/transcendence`
Issu de l'auto-review du dépôt 42Cursus (mode `/review` auto-review). Dernier projet du cursus : application web en microservices NestJS (jeu Pong multijoueur + comptes utilisateurs), orchestrée par `docker-compose.yml` (NGINX en frontal, `api-gateway`, `user-service`, `game-service`, PostgreSQL, stack de monitoring optionnelle via `profiles: ["monitoring"]`). Beaucoup de notions transverses sont déjà couvertes : JWT (`jwt-et-tokens.md`), TOTP/MFA en principe (`authentification-multifacteur.md`), hachage de mot de passe (`mots-de-passe-et-hachage.md`), ORM (`orm.md`), WebSocket/Socket.IO (`websocket-et-temps-reel.md`), architecture microservices/bases de données séparées (`microservices.md`), Docker Compose/volumes/réseaux/TLS auto-signé (déjà vus sur `inception`). Les points ci-dessous n'y sont pas.
- **Passerelle API (API Gateway) applicative, distincte d'un reverse proxy réseau** : `docker-compose.md` ne présente le reverse proxy (NGINX/Traefik) que comme une redirection réseau au niveau infrastructure ; `services/api-gateway` est un service applicatif à part entière (NestJS) qui reçoit toutes les requêtes du frontend sur un point d'entrée unique et les route vers le bon microservice interne (`UserProxyController`/`GameProxyController`, un contrôleur par domaine avec ses propres routes déclarées, ex. `@Post('auth/login')`), tout en gérant lui-même des préoccupations transverses que NGINX ne connaît pas (CORS via `app.enableCors()` dans `main.ts`, endpoint `/metrics` agrégé). Point notable : la passerelle elle-même ne vérifie PAS le JWT (aucun garde d'authentification dans `UserProxyController`) -- c'est chaque microservice en aval (`game-service/src/auth/jwt.strategy.ts`, `passport-jwt`, même secret partagé `JWT_SECRET`) qui revalide le token indépendamment ; la passerelle ne fait que router, la confiance n'est jamais déléguée à un seul point. Absent de Devpedia (aucun chapitre ne nomme le pattern API Gateway ni ne le distingue du reverse proxy réseau).
- **Pont entre un flux Web (`ReadableStream` de l'API `fetch`) et un flux Node.js (`stream.Readable`) pour relayer un contenu binaire sans le charger entièrement en mémoire** : `UserProxyController.forwardRequestWithImage()` (upload/téléchargement d'avatar) utilise `fetch()` pour interroger `user-service`, dont la réponse expose un corps au format `ReadableStream` du standard Web (API navigateur/`fetch`, pas l'API historique de Node.js) ; pour le retransmettre au client via la réponse Express (`res`, qui attend un flux Node.js classique), le code lit ce `ReadableStream` manuellement (`fetchRes.body.getReader()`) et réémet chaque chunk dans un nouveau `new Readable({ async read() {...} })` avant de le brancher sur `res` avec `.pipe()` -- un adaptateur manuel entre deux implémentations différentes du concept de flux (Web Streams vs Node.js Streams) qui coexistent dans l'écosystème JavaScript moderne, nécessaire ici car aucune conversion automatique n'existe entre les deux à cette version de Node. Absent de Devpedia (aucun chapitre sur les flux/streams en JavaScript/Node.js, ni sur la distinction Web Streams/Node Streams).
- **URI de provisionnement `otpauth://` pour l'enrôlement initial d'une application TOTP par QR code** : `authentification-multifacteur.md` explique le principe du TOTP (secret partagé, code recalculé des deux côtés) mais pas comment ce secret initial est concrètement transmis à l'application d'authentification. `TwoFAService.generateQRcode()` (`user-service`) construit cette URI avec `authenticator.keyuri(email, "Transcendance", secret)` (bibliothèque `otplib`), qui produit une chaîne `otpauth://totp/Transcendance:email?secret=...&issuer=Transcendance` -- un schéma d'URI standardisé (indépendant de tout fournisseur) que toute application TOTP (Google Authenticator, Aegis...) sait interpréter ; cette URI est ensuite encodée en QR code (`QRCode.toDataURL()`) pour être scannée, seul le secret contenu dans l'URI important réellement (le QR code n'est qu'un moyen pratique de le transmettre sans erreur de saisie). Absent de Devpedia (le principe du TOTP est couvert, pas le format concret de son échange initial).
- **Boucle de jeu autoritative côté serveur à tick fixe, taux de simulation découplé du taux d'émission réseau** : `PongRoom.start()` (`game-service`) fait tourner un `setInterval` à 60 Hz (`TICK_MS = 1000/60`) qui avance la simulation complète du jeu (position de la balle, collisions, score) uniquement côté serveur -- les clients n'envoient que leurs entrées (`up`/`down` via `updateInput()`), jamais leur propre position, et se contentent d'afficher l'état reçu (modèle **serveur autoritaire**, qui empêche un client de tricher en falsifiant sa position). Le pas de temps (`dt`) est plafonné (`if (dt > 0.05) dt = 0.05`) pour éviter qu'un ralentissement ponctuel ne fasse traverser un mur à la balle en un seul tick trop grand. Fait notable : l'état n'est diffusé aux clients (`io.to(roomId).emit('game_state', ...)`) qu'une fois sur deux ticks (`EMIT_EVERY_N_TICK = 2`) -- la simulation tourne plus vite que ce qui est réellement envoyé sur le réseau, pour économiser de la bande passante sans perdre en précision de calcul. `websocket-et-temps-reel.md` couvre le protocole WebSocket/Socket.IO utilisé pour la diffusion, mais pas ce pattern d'architecture temps réel (simulation autoritaire + tick rate distinct de l'emit rate), absent de Devpedia.

## 7. Notions repérées pendant l'auto-review du module `nps_qualite` (Backoffice-TC)
Issu de l'auto-review du dépôt Backoffice-TC (mode `/review` auto-review), périmètre = module `nps_qualite` (scores NPS véhicules neufs/après-vente par concession, primes qualité). Module simple côté backend (un seul endpoint `/api/nps_qualite/villes`, non bloquant, cf. `NpsController::villes()`) ; l'essentiel de la logique est côté frontend (`public/js/modules/nps_qualite/{index,calculette}.js`), qui lit un fichier de données statique généré par un outil externe (`window.NPS_DATA`, aucune notion de code côté projet). Transverses déjà couvertes (PHP/PDO, routage front controller, appels HTTP natifs) non redétaillées ici. Points ci-dessous absents de Devpedia :
- **NPS (Net Promoter Score)** : métrique métier connue (mesure de satisfaction/fidélité client), calculée ici par `calculNPS()` (`calculette.js`) comme `(promoteurs − détracteurs) / total × 100` à partir d'une note de 1 à 10 (détracteurs = notes 1-6, neutres = notes 7-8 exclues du calcul mais comptées dans le total, promoteurs = notes 9-10). Usage général au-delà de ce projet : mesure standard de satisfaction client utilisée dans énormément d'entreprises (support, SAV, expérience produit), pas propre à l'automobile. Absent de Devpedia (aucun chapitre Gestion de projet/KPI ne le nomme).
- **`ResizeObserver`** : `watchQualityOverflow()` (`index.js`) observe la largeur réelle d'un tableau (`getBoundingClientRect().width`) pour basculer vers une mise en page resserrée dès qu'il déborderait de son conteneur, recalculé à chaque redimensionnement sans écouter l'événement global `resize` de la fenêtre. `observateurs-et-limitation-de-frequence.md` couvre déjà `IntersectionObserver` (visibilité) et `MutationObserver` (changement du DOM), mais pas `ResizeObserver` (changement de *dimensions* d'un élément précis) : même famille d'API navigateur "callback sur changement, sans sonder en boucle", troisième membre manquant. Bon candidat pour compléter ce chapitre existant plutôt qu'un nouveau.
- **Un ancêtre avec `transform` change le point de référence d'un descendant `position: fixed`** : `registerDropdown()` (`index.js`) réparente chaque panneau de menu déroulant sous `<body>` avant de le positionner en `position: fixed` (calcul manuel dans `placeDropdown()`), avec le commentaire "même piège que `.combo__panel` du design-system" -- signe qu'il s'agit d'un problème récurrent dans ce projet. Raison : `positionnement.md` explique que `fixed` se positionne par rapport à la fenêtre et qu'un `transform`/une opacité < 1 crée un nouveau *contexte d'empilement* (comparaison de `z-index`), mais ne dit pas qu'un ancêtre avec `transform` (ou `filter`/`will-change`) devient aussi le point de référence géométrique (*containing block*) de ses descendants `fixed` -- qui cessent alors de se positionner par rapport à la fenêtre. C'est ce second effet (pas le `z-index`) qui casse un menu `fixed` placé sous un ancêtre animé en `transform` (ici `.ds-reveal`), d'où le contournement par réparentage sous `<body>`. Distinction absente de `positionnement.md`.
- **`conic-gradient()` pour un anneau de progression circulaire sans SVG** : `.calc-ring` (`nps_qualite.css`) dessine l'anneau de progression de la calculette qualité avec `background: conic-gradient(var(--ring-color) calc(var(--pct) * 1%), var(--c-chip) 0)` sur un élément rond (`border-radius: 50%`) -- un dégradé dont la couleur tourne autour d'un point central (contrairement à `linear-gradient`/`radial-gradient`, qui progressent en ligne droite ou en cercles concentriques), utilisé ici pour remplir angulairement un pourcentage du cercle sans dépendre de SVG (`stroke-dasharray`) ni de JS pour dessiner la forme. Absent de Devpedia (aucun chapitre CSS ne mentionne `conic-gradient`).
- **API navigateur `Fullscreen`** (`requestFullscreen()`/`exitFullscreen()`/événement `fullscreenchange`) : le mode présentation (`index.js`) bascule la page en plein écran au clic, et écoute `fullscreenchange` pour resynchroniser son propre état si l'utilisateur quitte le plein écran par un raccourci navigateur (Échap) plutôt que par le bouton de la page -- point notable, l'événement est nécessaire précisément parce que le plein écran peut être quitté par un chemin que le code n'a pas déclenché lui-même. Absent de Devpedia.
- **API navigateur `Clipboard`** (`navigator.clipboard.writeText()`) : le bouton "Copier le résultat" de la calculette écrit dans le presse-papiers système ; asynchrone et pouvant échouer (autorisation refusée), d'où le `try/catch` autour de l'appel. Absent de Devpedia.
- **Apache ECharts** (`echarts.min.js`, chargé en vendor local) : bibliothèque de graphiques JS utilisée ici pour le graphique d'évolution trimestrielle NPS/taux (`renderEvolutionChart()`), et déjà utilisée ailleurs dans le projet (module `wepo`). Absent de Devpedia (aucun chapitre ne nomme de bibliothèque de graphiques JS, seulement les équivalents Python `matplotlib`).
- **`table-layout: fixed` + `<colgroup>` pour des largeurs de colonnes autoritaires** (`nps_qualite.css`) : par défaut (`table-layout: auto`), un navigateur ajuste la largeur des colonnes au contenu réel des cellules ; `table-layout: fixed` fait l'inverse et impose les largeurs déclarées sur `<colgroup>` quel que soit le contenu, utilisé ici pour que plusieurs tableaux indépendants (un par marque) restent alignés colonne par colonne. Absent de Devpedia (aucun chapitre CSS ne mentionne `table-layout`).

Un fichier `.xlsx` stocke pour chaque cellule à la fois la **formule** et la **dernière valeur calculée mise en cache** (calculée par Excel au dernier enregistrement) ; par défaut, `openpyxl` renvoie la chaîne de formule (`"=A1+B1"`), pas le résultat -- `data_only=True` bascule sur la valeur en cache. Piège correspondant (non rencontré ici mais réel) : si le fichier n'a jamais été ouvert/recalculé dans Excel après une modification, la valeur en cache peut être absente (`None`) ou obsolète, `openpyxl` ne recalculant jamais lui-même une formule. Absent de Devpedia (aucun chapitre ne couvre la lecture/écriture de `.xlsx` par script, contrairement au PDF déjà couvert par `extraction-pdf.md`).
- **Authentification serveur-à-serveur par compte de service Google (JWT auto-signé), distincte du *Client Credentials* générique** : `oauth2-et-openid-connect.md` couvre déjà *Client Credentials* (un secret partagé prouve l'identité du service). Le compte de service Google (`google.oauth2.service_account.Credentials.from_service_account_file()` + `AuthorizedSession`) utilise un mécanisme différent : une **clé privée RSA** (jamais transmise sur le réseau) sert à signer soi-même un jeton JWT qui atteste de l'identité du service auprès de Google -- un flux normalisé par la RFC 7523 (*JWT Bearer Assertion Grant*), où aucun secret n'est directement échangé, contrairement à *Client Credentials*. Extension utile du chapitre existant plutôt qu'un nouveau chapitre.
